처리 유형

무엇이 어디로 가야 하는데, 안 오면 어떻게 되는지만 적었어요. 줄을 누르면 흐름도에서 상세 내용(감지 기준·처리·복구·근거)이 열려요. 아래의 "멈춤"은 모두 모터를 놓는 것이고 브레이크가 아니에요.

모듈(상자)이나 번호(구간)를 누르면 오른쪽에 처리 내용이 나와요. 상자 모서리의 점은 그 안에 "감지 없음"(빨강)이나 "약함"(주황) 항목이 있다는 뜻이에요.
선 모양과 글자는 전달 방식이에요: 굵은 실선 = 유선 LAN(Jetson ↔ Pi5 이더넷 직결), 점선 = Wi-Fi(Pi4·노트북은 Wi-Fi만 있음), 가는 실선 = 보드 안. 보드 사이 데이터는 ROS2(DDS) 토픽으로, 노트북 ↔ Pi4는 SSH로 오가요. 카메라·LiDAR·GNSS·VESC는 각 보드에 USB로 연결돼 있어요.
시간 표현: "받은 지 X초가 지나면" = 마지막으로 받은 뒤 X초 동안 새 것이 안 오면. "찍힌 시각이 X초 넘게 과거" = 데이터 안에 적힌 측정 시각이 지금보다 X초 넘게 이전이면(늦게 도착한 경우). "X초 넘게 미래" = 보낸 보드의 시계가 받는 보드보다 앞서 있는 경우.
위치문제 상황언제 알아채나그러면다시 정상이 되려면유형근거

발견 사항 F1~F19

미래 시각 허용치가 모듈마다 달라요 (F13)

받는 쪽비교하는 시각미래 허용과거 허용근거

GUI는 보드당 0.15초까지 맞았다고 보지만, Jetson 지도는 Pi5 시계가 0.05초만 앞서도 위치를 버려요. GNSS 수신기는 보드 시계가 UTC보다 늦으면 모든 epoch를 버려요.

끊김이 아래로 전파되는 순서

    보드 사이 물리 통로

    Jetson과 Pi5는 유선 직결과 Wi-Fi를 둘 다 갖고 있어요. Pi4와 노트북은 Wi-Fi만 있어요. 그래서 Pi4로 가는 위치·지도·주행 관련 데이터는 모두 Wi-Fi를 지나요.

    구간데이터통로양문제
    1. Jetson → Pi5OAK 좌·우 영상, IMU유선 + Wi-Fi 중복 (교실 Wi-Fi에서)약 7 MB/sWi-Fi 혼잡의 유력 원인 (F20)
    4. Jetson → Pi5ZED IMU·지자계유선 + Wi-Fi 중복작음영향 작음
    6. Pi5 → Jetson공용 위치·위치 상태유선 + Wi-Fi 중복작음 (20Hz)영향 작음
    5. Pi5 → Pi4공용 위치·위치 상태Wi-Fi만작음 (20Hz)Wi-Fi가 붐비면 0.5초 넘게 늦어 정지 (11-10 관측)
    10. Jetson → Pi4비용지도, 인지 상태Wi-Fi만중간Wi-Fi가 붐비면 늦어 정지
    11·12. 노트북 ↔ Pi4목표·출력 허용 / 플래너 상태 (SSH)Wi-Fi만작음끊겨도 감지 없음 (F2)

    F20. 같은 영상이 Wi-Fi로 한 번 더 가요 (추정, 근거 강함)

    11-10 관측: Pi4는 위치가 0.3→0.5초 늦게 와서 멈췄다 가기를 반복했는데, 같은 때 Jetson은 위치를 0.04~0.08초로 신선하게 받았어요. 그때 Pi5는 유선과 Wi-Fi로 각각 약 7 MB/s를, Jetson은 유선과 Wi-Fi로 각각 약 60 Mbps를 주고받고 있었어요.

    설정을 읽어 보니: 영상을 보내는 Jetson OAK는 유선만 쓰도록 되어 있지만, 받는 Pi5 VIO 설정(이름은 oak_fastdds_wired.xml)에 Pi5의 교실 Wi-Fi 주소가 들어 있어요. Pi5가 "Wi-Fi 주소로도 보내 달라"고 알리면, Jetson은 그 주소로도 보내고 리눅스가 그 패킷을 Jetson의 Wi-Fi로 내보내요. 그래서 같은 영상이 두 번 가요.

    핫스팟에서는: Pi5의 Wi-Fi 주소가 달라져 설정과 맞지 않으므로 저절로 유선만 써요. 교실 Wi-Fi에서만 생겨요.

    조치 (2026-11-11 12:32 Pi5 파일 수정 완료, 다음 시험이나 VIO 재시작 때부터 적용, 효과는 아직 확인 전): Pi5의 ~/nomad_ws/config/oak_fastdds_wired.xml에서 Wi-Fi 주소 한 줄을 빼요. Jetson·Pi4·GUI는 그대로예요. 단, Pi4 제어 방식이 vio_duty이면 Pi4가 VIO 값을 Wi-Fi로 직접 받으므로 끊겨요. 바꾸기 전에 확인해야 해요.

    확인 방법: 바꾸기 전·후에 Pi5 Wi-Fi 수신량(약 7 MB/s → 거의 0)과 Pi4의 위치 지연·정지 반복을 비교해요. 상세 변경안은 팀 작업 PC의 유선전용_변경안.md.

    확인 수준: 설정 파일과 네트워크 카운터가 맞아떨어지는 강한 추정이에요. 패킷을 직접 잡아 확인하지는 않았어요.
