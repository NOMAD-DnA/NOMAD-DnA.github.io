계산 출처 · 시각화 범위

2026-10-26 합의한 운용 정책: GPP는 주행 중 남은 경로를 검사하되, 정상이면 경로·중간 목표를 재발행하지 않습니다. LPP는 마지막으로 받은 경로로 계속 추종합니다. 정상 검사는 별도 GPP 상태와 내부 로그에 표시하며 발행 단계로 전환하지 않습니다. 목표 전환·경로 변경·무효화 시에만 관련 발행이 발생합니다. 현재 ROS 구현의 주기적 안전 경로 재발행과는 다른, 합의한 정책의 시연입니다. 실제 ROS 코드는 아직 변경하지 않았습니다.

관측된 통행 영역이 최종 목적지까지 연결되면 최종 목표로 전환합니다. 경로 버전은 새 경로 채택 시, 발행 번호는 새 경로 또는 빈 경로를 발행할 때 증가합니다. 정상 검사만으로는 두 번호 모두 바뀌지 않습니다.

실제 프로젝트 의 hybrid_astar.py, base.py, rpp.py, rollout.py, route_guard.py를 참고한 JavaScript 구현입니다. 경로를 미리 저장해서 재생하지 않습니다. GPP의 후보 노드 확장을 나누어 표시하고, 성공하면 전역 경로를 발행하는 단계를 거칩니다. RPP 내부 계산 → PlannedMotion → DriveCommand의 순서를 단계별로 관찰할 수 있습니다.

검증용 공통 설정: 지도 0.3 m, 축간거리 0.72 m, GPP 최대 조향 0.35 rad / RPP 0.4 rad, 최대 속도 0.5 m/s, 적응형 lookahead. 실제 통합 프로파일의 모든 파라미터를 재현하지는 않습니다. 비용 휴리스틱은 미리 계산하므로 Python의 지연 계산 구현과 탐색 순서가 다를 수 있습니다. 추종점은 후륜 기준 변환 경로 위의 점입니다. 초록 궤적은 이상적 차량 운동 모델의 결과입니다.

지도·경사 비용은 합성 입력입니다. 반경 관측과 직선 가림 검사를 통해 지도를 누적합니다(실제 카메라 인지가 아님). 5번 벽도 이 관측으로 드러납니다. 6번은 후진 제약만 분리해 보기 위해 과거 후방 관측을 초기 지도에 포함합니다. CorridorSelector의 관측 영역·중간 목표·안전한 경로 유지 흐름을 옮겼으며 후보 점수의 위험도는 합성 비용을 사용합니다. 관측 지원·경사 증가·후방 복구 gate 등 전체 ROS 계약은 이식하지 않았습니다. ROS 통신·인지·차량 물리·명령 선택기의 안전 계약 전체는 실행하지 않습니다. 오른쪽 파란 선·점은 발행된 GPP 경로를 차량 시점에 투영한 표시이며, 주황색은 RPP 계산 결과입니다. 화면 밖의 근접 추종점은 가장자리 안내로 구분합니다. HUD 안내선은 차선 인지 결과가 아닙니다. 화면의 탐색 속도는 설명을 위한 표시 속도이며 실제 연산 소요시간과 구분합니다.
