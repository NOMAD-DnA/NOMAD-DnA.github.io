NOMAD 전체 시스템 구조

센서 → 위치추정(VIO + 융합기) → 인지 → 매퍼(개선 매퍼) → 플래닝(Jetson) → 제어(Pi4 VESC), 그리고 노트북 GUI·기록까지 한 장에 정리했다. 2026-11-16 기준, 작업 기록·공유폴더 코드·설정 사본에서 확인한 내용이며, 확인하지 못한 것은 미확인, 짐작은 추정으로 표시했다.

Jetson Pi5 Pi4 노트북 위험·문제

전체 흐름 — 블록을 누르면 아래에 자세한 설명

선 굵기·글자는 실제 데이터 경로와 주기. 점선 = 무선(Wi-Fi/핫스팟), 실선 = 유선 또는 같은 보드 안.

전체 흐름 한 단락

Jetson의 OAK-D가 흑백 좌우 영상(10 Hz)과 IMU(200 Hz)를 100 Mbps 직결 유선으로 Pi5에 보낸다. Pi5에서는 Basalt VIO(odom 약 10 Hz)와 C++ GNSS(1 Hz)가 돌고, Ceres 융합기(발행 20 Hz, 최적화 2 Hz)가 GNSS를 drift_correction 방식으로 x·y·yaw에만 천천히 반영해 공용 위치를 낸다. Jetson에서는 ZED 영상 → SegFormer 야지 라벨(1 Hz), LiDAR(5 Hz), OAK 스테레오 점군(1~5 Hz)이 개선 매퍼로 모여 경사(중력 기준)와 의미 비용 지도를 만든다(지도 나이 약 0.9 s). 같은 Jetson의 플래너가 경유점 → Hybrid A* GPP(5 Hz) → RPP LPP로 경로를 짜 20 Hz DriveCommand를 무선으로 Pi4에 보내고, Pi4 제어기(50 Hz)가 ERPM(최소 1000)·서보(±35°)로 바꿔 VESC를 움직인다. 노트북 GUI는 SSH로 보드를 켜고 끄며, 받은 상태를 .nomad에 기록한다.

이전 페이지와 무엇이 달라졌나
  • 플래너 위치: Pi4 → Jetson (Pi4는 드라이버·제어기만 실행).
  • 매퍼: 기존 4프로세스·JSON 전달 → 개선 매퍼 단일 프로세스, 경사 기준 진행방향 → 중력.
  • 위치: GNSS를 창 최적화에 넣던 방식 → drift_correction(1 m당 2 cm만 반영), VIO 감시기 자동 재시작.
  • 제어: 0 A 관성 정지 → 브레이크 20 A + 핸드브레이크, 감속 정지 0.3 s, 서보 0.40 → 1.0/s.
  • 이전 판: 데이터 흐름·예외 처리(11-13), 새 매퍼 구조(11-13).
